# High level description

Create a tool that simplifies the process to getting samples onto the roland p6 and export patterns and samples back out. A user would create a configuration with a name, description and creation date. The user would browse a defined directory of samples, preview them and then assign them to a bank/pad.

The user can then mount the p6 and transfer the samples. A configuration can be picked at any point and sent to the p6.

A local database/storage will keep a record of the configuration. 

# Implementation

- Tool is implemented as a TUI, based on lazygit/lazydocker
- one pane lists all the previous configuration
- picking a configuration will list the sample/pad assignments
- one pane has a file browser that lists samples and allows the audio to be listened to
- keyboard shortcuts would allow a sample to be assigned to a pad, maybe key-chords, so A then 1 would assign to bank A pad 1. E then 4 would assign to bank E pad 4.
- sending to the device is a full overwrite of any pads that have been assigned. The p6 mounts as an import target, any files copied into the mounted drive will be imported whne confirmed on the p6.
- implemented as python using a tui library.
- copies file as is, in the future (see questions) we might consider other sample rates later
- configuration stores the filepath to the original sample and its pad assignmetn
- if a sample has been removed it is flagged to the user when they attempt to commit the configuration. the commit will not run
- exports out of the p6 will be defined later
- configurations should be stored as a local json file, ~/.config/p6-tool/configurations
- after the files are copied the user will be prompted to confirm the import on the device

# other details

- p6 is mounted as a folder
- 8 banks A-H
- 6 pads 1-6
- only one sample per pad
- we do not need to worry about existing content on the p6, it will be overwritten by the device on import
- commiting the configuration is a final task after the assignments are settled, the user can choose to save the configuration and not commit
- existing pad files will not appear in the mounted folder, the p6 exposes the empty directories.
- the device should not allow multiple samples to be assigned to the same pad, last picked wins
- info.txt is generated by the device and does not need to be written to

# questions

- would it be easy to control the sample rate that the file is sent as?
- need to find options for audio playback, ideally within the tool but could just attempt to open the file and rely on the OS to handle it
